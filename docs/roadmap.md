# 路线图

## 已实现：单队双赛事的招新与培养闭环

默认服务青岛理工大学机器人战队：沧溟 / MOVE 为同一支队伍的中英文名称，同时参加 RoboCon 和 RoboMaster。当前基线包括：

- 本地演示与正式环境管理员引导，管理员创建导师和面试官账号。
- 邮箱验证注册、必填个人资料与照片、PDF 简历、统一团队报名与审核；保留历史面试安排、评分及录取记录。
- 技术组首页、文件／PDF／视频知识库、作业与考核、定时文件或代码考试；仅电控、视觉算法、硬件提供编程题库。
- 私有文件上传、提交版本、导师评分与退回修改，以及 Judge0 兼容的单文件异步评测。
- 按组私有提问、工作人员解答、管理员公开已解答问答。
- 荣誉按人发放和 PNG／JPEG 预览，个人中心整合资料、个人档案与附件；管理员批量邮件。
- 角色工作台、成员列表、可配置品牌与本地队标上传，以及 Hydro 外部入口。
- 本地 SQLite、PostgreSQL 部署定义和基础持续集成。

验收以真实 API 与数据库结果为准：学生不能读取他人报名或荣誉，面试官不能处理未分配对象，未录取学生不能提交培养任务，未开考题目不能提前读取，评分不能越界，旧提交不能覆盖新版本的审核结果。SMTP 与真实 Judge 执行服务仍需另行配置和部署验收。

## 第二阶段：在一个方向内试运行

- 通过实际招新样本验证字段、状态与面试评价方式。
- 完善招新批次、赛季归档和各角色资源范围。
- 报名草稿自动保存、通知中心、找回密码和访问限流。
- 完成 PostgreSQL 集成验证、并发校验与备份恢复演练。
- 配置真实 SMTP，验证邮箱送达、退信与批量发送的运维流程。
- 配置独立 Judge 服务，验证真实编译、资源限制、沙箱隔离与异常恢复。
- 根据试用规模提供对象存储、文件归档、删除回收与配额管理。

验收：一个方向独立完成招新与培养，异常中断后数据可恢复，内部评价不会暴露给候选人，关键记录可追溯。

## 第三阶段：深化考试与 Hydro 集成

- 在现有定时文件／代码考试与单题练习之外，补充多题试卷、考试成绩单和更完整的教师工作流。
- 验证所选 Hydro 版本的插件与接口。
- 保存身份映射、考试关联及题目来源。
- 同步成绩并提供人工重试、幂等处理与同步日志。
- 将编程测评与人工工程评价并列展示，保留各自评价依据。

验收：重复同步不重复计分，失败可重试；外部测评暂时不可用时，报名、面试和任务提交继续工作。

## 第四阶段：工程项目协作

- 机器人／子系统项目、负责人和里程碑。
- 接口文档、实机验收、联调问题和故障复盘。
- 成员能力档案与工程成果关联。
- 赛规知识题增加赛事、赛季、规则版本、出处与复核状态。

验收：至少一个机器人子系统的任务、成果、接口与故障记录可沿项目和成员两个维度查阅。

## 按需扩展

设备借用、库存、采购与预算需要在团队持续使用后单独确认流程。初期不建设全功能即时聊天，不做自动录取推荐，不重写 Hydro 判题引擎，也不将 OJ 分数当作机器人工程能力的唯一指标。
